# hao.AI — Project Overview

## Overview

hao.AI is a private, single-user web app for practicing spoken Mandarin
Chinese conversation. A signed-in user opens the app and lands directly on one
screen where an AI tutor has already posted an opening line in Chinese. The user
presses and holds a microphone button to speak a Chinese sentence; the audio is
transcribed, sent to a language model that replies in character at the user's
selected HSK level (1–6), and the reply is spoken aloud and shown as three
stacked lines — Chinese characters, pinyin, and an English translation — with a
collapsible correction of what the user said. The conversation is turn-based
(speak, wait, hear the reply), stored so it survives a page reload, and browsable
later from a history panel. Authentication is handled by Clerk with public
sign-up open — anyone can create an account, no allowlist.

## Goals

1. Let the user complete a spoken Chinese exchange of at least 10 back-and-forth
   turns without touching the keyboard, start to finish, on current Chrome or
   Safari (desktop and iOS).
2. Render every AI turn with correct pinyin, verified by spot-checking the
   heteronyms 还, 得, 长, 银行 against a deterministic library (`pinyin-pro`), not
   model-generated pinyin.
3. Keep the AI's vocabulary within the selected HSK level for at least 90% of
   content words, measured by checking reply tokens against the bundled
   cumulative HSK 1–6 word lists.
4. Return the full turn round trip (release mic → spoken reply begins) in under 5
   seconds at the 50th percentile on a normal home connection.
5. Hold total third-party API cost at or below US$5 per month at a usage level of
   ~20 sessions/month × ~15 minutes.
6. Guarantee that no unauthenticated request ever reaches DeepSeek, Groq, or
   ElevenLabs, verified by an automated test per API route.
7. Cap spend even under a client bug or abuse: a shared per-user limit of 30
   turns/minute and 300 turns/day (across transcribe/chat/speak) enforced
   server-side, plus a hard monthly spending cap set in each provider
   dashboard.
8. Persist conversations so that reloading the page mid-conversation restores the
   full transcript, and the last 50 conversations per user remain openable from
   history.
9. Ship a deployed, login-gated public URL that the user can use for one full
   week without any code change.

## Core user flow

1. The user opens the deployed URL.
2. If not signed in, Clerk shows the sign-in/sign-up screen. The user signs in
   or creates an account with email or Google — sign-up is open to anyone.
3. The app loads the conversation screen. If the user has an in-progress
   conversation, its transcript is restored. If not, the server seeds a new
   conversation with one AI opening turn (for example 你好！今天想聊什么？).
4. The AI opening turn renders as three lines: pinyin (muted, above), Chinese
   characters (serif, large), English translation (muted, below). Its audio
   plays automatically once, generated by ElevenLabs.
5. The user checks the HSK level tag in the top-right corner. To change it, the
   user taps the tag, picks a level 1–6 from the popover, and the choice is
   saved.
6. The user presses and holds the microphone button in the bottom bar and speaks
   one Chinese sentence. While held, a pale-blue ring around the button reacts to
   voice volume.
7. The user releases the button. Recording stops. If the clip is longer than 60
   seconds or larger than 1 MB, the app rejects it locally and shows an error.
   Otherwise the audio uploads to the server.
8. The server checks the user's rate limits. If exceeded, it returns a "slow
   down" state and makes no provider calls. Otherwise it continues.
9. The server sends the audio to Groq (`whisper-large-v3-turbo`) and gets
    back the user's Chinese text. This appears in the transcript as the
    user's turn, labelled `you`.
10. The server sends the full conversation transcript plus the system prompt
    (tutor persona, "short replies", "restrict to HSK N vocab", and the bundled
    cumulative HSK word list) to DeepSeek and receives structured JSON:
    `{ reply_zh, reply_en, correction }`.
11. The server converts `reply_zh` to pinyin with `pinyin-pro` and stores the
    new turn pair in the database. (An earlier design also flagged
    content words outside the selected HSK list; that flagging was built
    and then removed for inaccuracy — see `progress-tracker.md`.)
12. The server sends `reply_zh` to ElevenLabs at natural speed and returns
    the reply data and audio to the browser; the browser applies its own
    playback-rate multiplier (0.75x/1x/1.5x) on top.
13. The browser appends the AI turn (pinyin, Chinese, English) to the
    transcript, plays the audio once, and scrolls the transcript to the
    newest turn.
14. Under the user's turn, a collapsed "correction" disclosure holds the model's
    feedback. The user can expand or ignore it.
15. The user repeats steps 6–14. Each AI turn has a replay button that replays
    its audio.
16. At 25 turns in the conversation, the input is disabled with a prompt to
    start a new conversation.
17. The user taps "new conversation" at any time. The current conversation is
    archived to history and a fresh conversation with a new AI opening turn is
    started.
18. The user taps the history icon. A panel lists past conversations, newest
    first, each showing its date in monospace and either an LLM-generated
    title (once DeepSeek has produced one, best-effort after the first user
    turn) or, until then, the first line of its opening turn. Tapping one
    loads that transcript read-only. A back action returns to the live
    conversation.
19. The user closes the tab. On the next visit, flow resumes at step 1; the last
    in-progress conversation is restored at step 4.

## Features by category

### Conversation
- Turn-based spoken exchange: press-and-hold to record, release to send.
- Type/talk toggle: the user can switch to a typed-text input and send a
  message instead of speaking, using the same conversation pipeline.
- AI opening turn seeded server-side on every new conversation.
- Each AI turn rendered as pinyin + Chinese + English, all visible at once.
- Deterministic pinyin from `pinyin-pro`, not model output.
- Automatic one-time audio playback of each new AI turn.
- Per-turn replay button for AI audio.
- Full transcript resent to the model each turn (no summarization).
- 25-turn cap per conversation, then a forced "new conversation".

### Learning support
- HSK level selector (1–6) in a corner popover, persisted per user.
- System prompt constrains the model to the selected level's cumulative HSK
  vocabulary.
- Display Support toggle (All / Hanzi+Pinyin / Hanzi Only / Audio) controlling
  which of an AI turn's lines are shown, persisted client-side like the HSK
  level (added 2026-09-12).
- Collapsible per-turn correction of the user's Chinese (more natural phrasing,
  grammar fixes) from the same model call, styled as a "Native Polish Tip"
  callout (renamed 2026-09-12).
- Per-message speaking-rate control (0.75x / 1x / 1.5x), applied client-side
  to TTS playback via `HTMLAudioElement.playbackRate` — selected per AI turn,
  not a single app-wide setting (changed from a global toggle 2026-09-12).

Out: a visible "above level" indicator on content words outside the selected
level was built and then removed for inaccuracy (dictionary max-matching
misfired in practice — see `progress-tracker.md`).

### Accounts and access
- Clerk authentication (email or Google), public sign-up open to anyone.
- Server-side session check (`requireUser()`) on every API route.
- Clerk user button for sign-out.

### History and persistence
- Conversations and turns stored in Postgres (Neon) via Drizzle.
- In-progress conversation restored on page load.
- History panel: list of past conversations with date and a DeepSeek-generated
  title (falls back to the opening line's preview until a title exists),
  opened read-only. Conversations can also be deleted from history (the
  active conversation cannot be).
- Retention cap of 50 conversations per user; oldest pruned on overflow.

### Safety and cost control
- Per-user rate limits: shared bucket of 30 turns/minute, 300 turns/day across
  transcribe/chat/speak, enforced before any provider call.
- Input caps: audio ≤ 60 s and ≤ 1 MB (client-side), transcribed text ≤ 500
  characters (server-side).
- 15s timeout on every outbound provider call (DeepSeek, Groq, ElevenLabs),
  surfaced to the user as a recoverable error rather than hanging.
- Hard monthly spending caps configured in Groq and ElevenLabs dashboards;
  DeepSeek balance is prepaid.
- All provider API keys server-side only, never in the client bundle or
  responses.
- Every database query scoped by Clerk user ID.
- Offline detection and per-action loading/error states (transcribing,
  fetching a reply, loading audio, loading history) so every failure path
  shows a recoverable message instead of a blank screen or silent hang.

### Interface
- Single screen plus Clerk sign-in/sign-up; no other routes.
- Light/dark theme toggle (top-right icon), persisted client-side; applied
  before first paint to avoid a light-mode flash. Clerk's sign-in/sign-up
  widgets follow the same toggle via a light/dark appearance config.
- minimalist-ui visual language: warm off-white canvas, flat 1px borders, no
  drop shadows, Phosphor icons, no emoji, muted-pastel accents used only for
  semantic states.
- Serif Chinese "hero" line; monospace pinyin and metadata; geometric sans for
  UI.
- Radix primitives (Popover, Dialog, Collapsible) plus Tailwind; no component
  library.
- Press-and-hold mic button, charcoal at rest, voice-reactive pale-blue ring
  while recording, still when idle.
- Fixed bottom control bar with backdrop blur.
- Responsive from 400 px to desktop, ≥ 16 px side gutter, no horizontal scroll.

### Platform and deployment
- Next.js app deployed on Vercel, `git push` to deploy.
- Server-side API routes proxy every call to DeepSeek, Groq, and ElevenLabs.
- Environment variables split between Vercel preview and production.

## In scope

- One conversation screen and the Clerk sign-in/sign-up screen.
- Clerk auth with public sign-up open to anyone.
- Press-and-hold voice recording via the browser MediaRecorder API.
- A type/talk toggle letting the user send a typed message instead of a
  voice recording, through the same conversation pipeline.
- Speech-to-text via Groq (`whisper-large-v3-turbo`).
- Conversation replies via DeepSeek V4, returned as structured JSON
  (`reply_zh`, `reply_en`, `correction`).
- Deterministic pinyin generation via `pinyin-pro`.
- Text-to-speech via ElevenLabs, with a client-side, per-message
  0.75x/1x/1.5x playback-rate control.
- HSK 1–6 level selector, persisted per user, injected into the system prompt
  along with the bundled cumulative HSK word lists.
- Display Support toggle (All / Hanzi+Pinyin / Hanzi Only / Audio), persisted
  client-side.
- Collapsible per-turn correction of the user's Chinese, styled as a "Native
  Polish Tip" callout.
- Automatic and manual (replay) audio playback of AI turns.
- Postgres (Neon) storage of settings, conversations, and turns via Drizzle.
- Restore of the in-progress conversation on load.
- History panel listing the last 50 conversations (DeepSeek-generated titles,
  delete support), opened read-only.
- 25-turn cap per conversation with a forced new conversation.
- Per-user rate limiting (shared 30/minute, 300/day bucket) and input size

- 15s timeout on every provider call, with a recoverable error on failure.

## Out of scope

- Scenarios, role-play prompts, target-phrase lists, and scenario completion
  tracking.
- Pronunciation scoring, tone scoring, or any per-syllable assessment of the
  user's speech (no Azure Pronunciation Assessment).
- Cross-session memory: the app does not summarize past conversations or carry a
  learner profile between sessions. HSK level is the only persistent learning
  state.
- Spaced-repetition review, flashcards, saved vocabulary lists, or a vocabulary
  browser.
- Streaks, XP, points, levels, badges, progress charts, or any dashboard or
  statistics screen.
- A curriculum, lesson list, unit structure, or unlock progression.
- Custom registration UI, email verification flows, password reset UI,
  per-user billing, or subscription plans (Clerk's hosted sign-up/sign-in
  handles registration and verification directly; sign-up is open, not
  self-service beyond what Clerk provides out of the box).
- Storage of audio files. TTS audio is regenerated from text on replay; user
  recordings are streamed to the transcription API and discarded.
- A settings page or profile page beyond the corner HSK selector and the Clerk
  user button.
- An onboarding flow, tutorial, or first-run walkthrough.
- Real-time or streaming conversation, barge-in, or sub-second latency. The app
  is strictly turn-based.
- Handwriting practice, character stroke-order practice, or reading/writing
  exercises.
- Native iOS or Android apps; desktop app packaging.
- Offline support or a service worker.
- Guaranteed support for Firefox or older Safari versions; the target is current
  Chrome, Safari, and Edge.
- Multiple languages. Mandarin Chinese only.
- Team features, sharing a conversation, exporting a transcript, or public links.
- WAF/DDoS protection beyond Vercel's built-in, CAPTCHA, a secrets manager,
  audit logging, or intrusion detection.

## Success criteria

- An unauthenticated request to any API route is rejected (verified by an
  automated test per route).
- A signed-in user opening the app sees a conversation screen with
  one AI opening turn already present, its audio playing once automatically.
- The user can press and hold the mic, speak a Chinese sentence, release, and
  within 5 seconds (median) see their transcribed turn and hear the AI's spoken
  reply.
- Every AI turn shows Chinese characters, pinyin, and an English translation
  simultaneously; the pinyin for 还, 得, 长, and 银行 in a crafted test
  conversation matches the correct reading for the context.
- Switching the HSK selector from 1 to 5 produces visibly harder vocabulary in
  subsequent replies; the selection persists after a page reload and across
  devices.
- Each user turn has a collapsible correction that expands and collapses; each AI
  turn has a replay button that replays its audio.
- Reloading the page mid-conversation restores the complete transcript in order.
- After 25 turns, the input is disabled and prompts the user to start a new
  conversation; "new conversation" archives the current one and starts a fresh
  one with a new opening turn.
- The history panel lists past conversations newest-first with date and preview
  text; opening one shows its transcript read-only; a 51st conversation removes
  the oldest.
- Sending a 31st turn within one minute, or a 301st within one day, across
  transcribe/chat/speak combined, returns a "slow down" state and triggers no
  provider call.
- Uploading audio longer than 60 seconds or larger than 1 MB, or sending more
  than 500 characters of text, is rejected with a clear error and no provider
  call.
- Groq and ElevenLabs each have a hard monthly spending cap configured; the
  DeepSeek account is prepaid with a low balance.
- No provider API key appears in the client bundle or any network response
  visible to the browser.
- Every failure path — microphone permission denied, transcription failure,
  DeepSeek timeout, TTS failure, offline, rate-limited — shows a recoverable UI
  state rather than a blank screen or an unhandled error.
- The layout has no horizontal scroll and keeps a side gutter of at least 16 px
  from 400 px width up to desktop.
- `npm run build` succeeds and `npm audit` reports no high or critical
  vulnerabilities.
- The app runs on its deployed Vercel URL, behind Clerk login, and is used for
  seven consecutive days with no code change.
